# V2 기상 통계 수정 맥락 (2026-09-21)

## 결론

- 서로 다른 두 문제를 구분한다. **원본 저장 경로의 위험**과 **원본에서 파생한 통계의 중복 집계**는 별개다.
- 지금까지 확인한 운영 DB에서 원본 오염의 증거는 발견되지 않았다. 따라서 원본이 실제로 오염됐다고 쓰지 않는다. 다만 모든 원본 값의 정확성을 증명한 것도 아니다.
- 이번 통계 수정은 원본 테이블을 바꾸지 않고 파생 검증·집계를 새로 만든 작업이다. 발견한 집계 오류는 수정·대조·배포했다.

## 앞선 원본 저장 방어 수정

- `3ca92df`: 초단기실황 API가 재시도 끝에 완전히 빈 배열을 반환하면, 기본 `pty=0`, `rn1=0` 관측을 만드는 대신 해당 격자의 저장을 건너뛴다.
- `c6a005e`: 단기예보 API가 완전히 비거나 대상 시각의 유효한 `POP`가 없으면 예보 원본과 지도용 값을 갱신하지 않는다. 지도는 조회 시 마지막 유효 POP를 보여준다. 따라서 발견했던 **빈 응답 → 가짜 강수 0/POP 기본값 저장** 경로는 앞으로 차단된다.
- 이것은 과거 원본을 소급 정정한 작업이 아니다. 일부 카테고리만 빠진 실황 응답 등 다른 경계 사례까지 모두 차단했다고 주장하지 않는다. 이 별개 가능성을 이미 해결한 _완전 빈 응답_ 문제와 혼동하지 않는다.
- 백업 검사에서는 관측 원본 51,912건 중 완전히 빈 실황 응답 저장의 특징인 `tmp IS NULL`이 0건이었다. 저장된 예보 69개 발표 회차는 각각 252개 지역을 포함했다. 대량 원본 오염의 흔적은 찾지 못했지만, 이 검사만으로 일부 누락까지 배제할 수는 없다.

## 이번 파생 통계 수정

- 종전 `forecast_accuracy_stats`는 같은 관측 시각·지역에 대응하는 여러 예보 발표 회차를 집계해, 의도한 **관측 하나당 직전 발표 회차의 예보 하나**라는 표본 정의와 달랐다. 백업 시점 종전 집계의 표본 합계는 185,220건이었다.
- `ae9dfb7`: 원본 `weather_forecasts`와 `weather_observations`를 보존하고, 선택된 예보·관측 한 쌍을 `forecast_verifications`에 `(target_time, sigungu_code)` 기본키로 저장한다. `verified_accuracy_stats`는 이 표본의 `지역 × POP`별 파생 집계다. `verified`는 예보가 적중했다는 뜻이 아니라 실황과 짝지어 검증 가능한 표본이라는 뜻이다.
- 발표 회차 선택: 관측 00~02시 → 전날 23시 발표, 03~05시 → 당일 02시 발표, 이후 3시간 간격. 맞는 발표 회차가 없으면 이전 회차로 대체하지 않는다.
- 백업 시점 새 표본은 `252개 지역 × 206개 관측 시각 = 51,912건`이다. 발표 회차로 풀면 `252 × (69회 × 3시간 - 마지막 미관측 1시간)`. `0~100`은 POP 값의 범위이지 표본 수에 곱하는 항목이 아니다. 해당 백업에 실제 등장한 POP는 `0, 20, 30, 60, 70, 80`뿐이다.
- 백업 복사본과 운영 DB 백필에서 검증 행 51,912건, 집계 합계 51,912건, 원본 매칭 값 불일치 0건, 835개 집계 구간의 재계산 차이 0건을 확인했다. 이 대조는 **집계가 저장된 원본에 충실하다**는 뜻이지, 기상청 원응답과 모든 저장 원본의 진위까지 증명하지는 않는다.
- 백업: `/Users/spoy/Downloads/ohumbrella-db-backup-20260921-B3rafk/weather-consistent.sqlite` (`PRAGMA integrity_check = ok`). 기존 원본·기존 통계 테이블은 삭제하거나 수정하지 않았다.
- `ae9dfb7`을 `main`에 푸시하고 noderunner의 `ohumbrella-server`에 배포했다. 서버에서 `yarn install --immutable` 후 린트·타입 검사·테스트 5개가 모두 통과했고 API가 HTTP 200으로 새 표본 51,912건을 반환했다.

## 이력서·포트폴리오에서의 해석

- V2의 집계 기준 오류를 V1의 약 30개월·11만 건 이상·POP 30% 약 6.4% 수치가 틀렸다는 증거로 **자동 확장하지 않는다**. V1 수치의 정의와 근거는 별도로 확인해야 한다.
- “확인된 원본 오염”이나 “모든 누락의 정합성 보장”처럼 입증하지 못한 표현은 쓰지 않는다. 반대로 이번 일을 전체 원본이 심각하게 오염된 사건으로 부풀리지 않는다.
- AI로 V2 MVP를 빠르게 만든 경험과, 이후 집계 정의를 원본·테스트·백업 대조로 바로잡은 경험을 구분해 서술한다. 이는 실제로 드러나 수정한 검증 문제이지, 막연한 ‘이해 부채’만의 사례가 아니다.
