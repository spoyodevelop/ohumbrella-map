# 리팩터링 체크리스트

## 날씨 데이터 계약

- [ ] 클라이언트와 서버가 공유하는 날씨 API 계약을 만든다.
- [ ] 기상청 원본 `PTY` 코드와 내부 `precipitationType`을 분리한다.
- [ ] 기존 DB의 `pty` 컬럼과 내부 타입 사이에 명시적인 변환 경계를 둔다.
- [ ] 서버 `WeatherRecord`를 저장 레코드와 API 응답 타입으로 분리한다.
- [ ] 중복된 `pop`과 `kmaPop`의 역할을 정리한다.
- [ ] 숫자로 전달되는 `isRaining`을 boolean으로 바꿀지 결정한다.
- [ ] DB 컬럼 이름 변경은 별도 마이그레이션 작업으로 진행한다.

## 이름과 주석

- [ ] `pop`, `rn1`, `tmp`, `sky`는 API 경계를 정리할 때 도메인 이름으로 바꾼다.
- [ ] 코드 내용을 되풀이하는 주석은 이름을 개선한 뒤 제거한다.
- [ ] 기상청 제공 시각과 재시도 정책처럼 외부 제약을 설명하는 주석은 유지한다.
